# dsh-session-recycle

给 **DeepSeek Harness (DSH)** 加会话删除 —— 而且是**删进回收站**，随时能还原。

DSH 官方只有「归档」，没有删除。社区插件有，但都是**永久删除、无回收站**。  
这个插件补上那块安全网：删错了，在插件面板里点还原就行。

> **English**: Delete DSH sessions from the UI — into a recycle bin, not into oblivion.  
> Sidebar menu + header button, native tool, no extra HTTP route.

---

## 特性

- **回收站，不是火葬场** —— 删掉的会话进插件自己的回收站（`$DSH_HOME/session-recycle-store/`），  
  随时还原。还原 = 反向 rename，也是瞬间完成
- **秒删** —— 删除、还原、彻底删除都是**一次同卷 rename**（实测 ~20ms），  
  三平台同一套代码，不起任何子进程
- **彻底删除** —— 会话日志 + 统计缓存 + 工作区分组记录一起清，不会残留成「未分组」幽灵条目
- **不留空壳** —— 删空的工作区分组和它在 `sessions/` 下留下的空文件夹可以一起清掉，  
  不用自己一个个去翻磁盘
- **一次删一批** —— 设置里是一张分页的会话列表，**按分组分块**、筛选、全选、一次请求删完；  
  删除行为的勾选收在标签条右侧的「配置」里，页面上只有两个列表
- **两个入口** —— 侧栏会话行 `...` 菜单，和会话标题栏的垃圾桶按钮
- **跨站防护** —— 客户端路由校验 Host / Origin / sec-fetch-site，不让别的网页驱动你的删除
- **运行中也能删** —— 先 cancel 并等 agent 静默，再动手；不会被后续 flush 复活
- **中文 / English** 双语，跟随 DSH 语言设置
- **零依赖** —— 不装任何第三方包，无安装脚本

## 使用

侧栏会话行 → **`...`** → 「删除会话」，  
或会话标题栏 → **垃圾桶图标**。

弹窗会显示会话名和序列号，勾选确认后才会执行。

**删除的是当前正在看的那个对话时**，右侧面板会**清空**，而不是自动跳到列表里的  
下一个 —— 下一个该看哪个是你的选择，替你挑是一种猜测。左侧列表里点一下即可。

### 设置

设置里只有**一个**分区：**会话删除**。它上面是一条**标签条**，两个列表是它的两个标签页；
每个标签右侧有个 **?**，悬浮才展开它那一页的说明 —— 页内不再摆解释文字：

```
[会话列表 62 ?] [回收站 3 ?]                                   [配置]
会话列表 ──────────────────────────────────────────────────────────
[筛选（标题 / 目录 / 序列号）                                          ]
☑ 全选  [刷新]                                        已选 2 条 [删除所选]
共 62 个会话        第 1/2 页  [上一页] 1 2 [下一页]                  每页 50
┌──────────────────────────────────────────────┐
│ my-project                                         4 │
│ ☑ 修复登录 bug                               │
│   my-project/src · 2026/01/15 09:41:22       │
│ ☐ 重构结算模块                                │
│   my-project/settle · 2026/01/15 09:12:03    │
│ dsh                                                 2 │
│ ☐ a3f1c2d4-…（没有标题时用 id 兜底）          │
│   dsh/sandbox · 2026/01/14 18:02:10          │
└──────────────────────────────────────────────┘
```

**工具栏是两行**：**筛选框独占第一行**（整行宽），操作按钮在第二行，由**全选框**打头，  
贴在最左边 —— 和每一行自己的复选框在同一列上，所以「勾一行」和「勾全部」是同一个动作  
的两种粒度，不用去找。挤在一行时筛选框只会剩下 140px，夹在按钮中间，谁也不舒服。

两个列表**曾经是两个分区**（设置里两条并排的导航项）。合回来是因为那两条导航项  
读起来像两件事，实际是同一件事的两面 —— 一个决定「删什么」，一个负责「撤销删除」——  
而且把回收站挪到隔壁之后，「列表里那个空壳其实是能还原的」这件事就看不见了。  
现在：同一页面，同一个工具栏词表，一次点击就能来回切。

- 标签上的**数字**是各自列表的条数，也就是「值不值得点过去看一眼」的那一个数字。  
  两个数字都在开页时就位，不用先点进去；回收站那个由标签条自己读一次（它的列表  
  要等点过去才加载），删完一批会话后也会跟着涨
- **来回切不丢勾选**：两个列表一旦打开过就留在树上（另一个只是隐藏），  
  所以勾好一批再去看一眼回收站，回来勾还在
- 删除行为的开关都在标签条右边的**配置**按钮里：它们管的是两个列表  
  （回收站的开关也管着删除），所以不跟着标签来回跑

#### 会话列表（第一个标签）

这是**会话列表**：整个会话库一次列出，勾选后一次删掉多个，  
不用再去侧边栏一个个找、一个个点菜单。

- **筛选**同时匹配标题、项目目录和序列号；改筛选条件后自动回到第 1 页
- **按分组分块**：同一个工作区分组的会话排在一起，块与块之间是一条**小标题**，  
  上面写着分组名和这一组有几条（`my-project 4`）。没进任何分组的排在最后，  
  统一挂在「未分组」下 —— 那正是它们在侧栏里的处境。  
  分组名读的是 workspace 注册表里的当前名字，所以你给分组改名，这里跟着变
- 列表**分页**：每页 20 / 50 / 100 / 200 条可选（默认 50），页码按需折叠成  
  `1 2 … 9 10`。页大小只记在本机，不影响别人也不影响 host
- **全选是全量，不是「本页」**：勾上第二行最左边那个框，**整个筛选结果**一起被勾上 ——  
  60 条里翻到第 2 页，那 10 条同样在勾选里。想只删一部分就用筛选把范围缩小，  
  筛选是什么，全选就是什么。翻页时已勾的**保留**，工具栏一直显示「已选 N 条」
- 点「删除所选」要不要先确认，读的是配置里&#x7684;**「删除会话前先确认」**&#x5F00;关 ——  
  和侧边栏右键菜单里那条删除**共用一个开关**：关掉它，一次点击就是一次删除。  
  要确认时，确认条就地弹在原处（页面里已经是设置窗口了，再叠一层弹窗只会把人  
  绕晕），确认后**一次请求**删完整批
- **例外**：回收站关闭时，不管开关怎么设都会先确认一次，确认条也改成红色警告，  
  明确告诉你这是**永久删除**、无法还原 —— 这个开关管的是「别烦我」，  
  不是「我同意丢数据」，配置里那一行也会写明原因

#### 配置（标签条右侧）

**配置**按钮打开删除行为设置 —— 三个开关加一个「空分组与空目录」清理：

| 设置             | 默认    | 说明                                   |
| -------------- | ----- | ------------------------------------ |
| 删除时移入回收站       | 开     | 关闭后删除不可恢复                            |
| 删除会话前先确认       | 开     | 关掉后点删除直接执行，不再弹确认框（回收站关闭时例外：永久删除仍会确认） |
| 删除后自动清理空分组与空目录 | **关** | 勾上后，删会话时顺手清掉被删空的工作区分组和它留下的空文件夹       |

每一行只有**标题 + 勾选框**，解释挂在标题右侧的 **?** 上，悬浮（或键盘聚焦）展开；  
弹窗自己那句「这里的勾选改完立即生效」也收进了标题下方那一行的 **?** 里，  
不再是一段横在第一个控件前面的文字。

这不是为了好看。这个弹窗宽 **380px 且 `overflow: hidden`**，长解释留在行内时  
每一行都被撑成三四行高，旁边那个「清理」按钮会被挤到**换行**。  
挪进气泡之后，行恢复了本来的一行高，按钮也不再被挤。

气泡里是**分点**的，一点一个意思；带**背景色、边框和阴影**，和弹窗内容隔开，  
所以它是"浮在上面的一层"，不会被误读成正文。

**展开方向按位置定，不是统一一个方向**：弹窗里那几行**一律向上开** —— 弹窗裁掉溢出内容，  
最后一行下方只剩 79px，向下开就会被切掉；向上开时前几行上方有标题让出的空间，  
最长的那个（自动清理，5 点、192px 高）还余 66px。而**弹窗自己那一行说明在标题正下方**，  
上方没有空间，所以它**向下开**。标签条上的两个问号同理向下。

宽度取**固定 260px**，不随标题长短伸缩：按标题宽度取百分比时，长标题会把气泡压成  
一条窄柱，文字长高之后反过来逆着展开方向顶出边缘。

**「删除后自动清理空分组与空目录」**&#x662F;一个勾选框，因为这件事只有做与不做两种答案：

- **勾上**：每次删除都检查它所属的工作区是不是已经空了。空了就连分组一起移除，  
  并在同一条横幅里报数（`已删除 3 个会话，移除 2 个空分组并清理 2 个空目录`）。  
  适合「全选删除」这种一次清空的用法 —— 否则删完一次，侧边栏还留一排空壳
- **不勾**（默认）：什么都不动。一个空了的分组往往是你还在用的项目，  
  该不该消失得由你说了算

"分组"和"磁盘上的空文件夹"是一对：DSH 给每个项目目录在 `$DSH_HOME/sessions/`  
下留了一个文件夹（如 `--d-work-proj--`），会话删光后它就成了空壳。  
这个文件夹是**推导出来的索引**，不是项目本身 —— 真项目目录和会话日志一个都不会动。

清目录时清的是**这次删除正好弄空的那些**，不是"按项目名猜一个名字去删"，  
而且**两个目录都要清**：

- **分组目录**：`--d-work-mono--`（工作区自己的路径编出来的）
- **会话自己的目录**：会话在**子目录**里打开时，DSH 把它放在另一个文件夹里，  
  如 `--d-work-mono-apps-web--`

只清分组目录会漏掉后面这一种，表现就是开头那句话：**分组没了，空目录还在**。  
两个都清，才叫"清干净"。安全性由 `rmdir` 保证：它拒绝非空目录，所以同一个文件夹里  
还有别的会话时，那个文件夹一根汗毛都不会少，也不会被误报成"已清理"。

同一处的**空分组与空目录**一行会显示当前各有多少（`当前有 2 个空目录、1 个空分组`），  
点「清理」一次清完：**没有会话的分组**会被移除，**确实是空的**文件夹会被删掉，  
非空的目录和有会话的分组碰都不碰，连按两次和按一次一样。

它和上面的开关**不是重复**，而是兜底 —— 开关只在**本插件删除会话**的那一刻触发，  
只管「这次删除刚弄空的那些」。下面这些它看不见：

- 开关关着的时候删掉的会话
- 用别的方式删掉的会话（DSH 自带删除、手动删文件、在别的机器上删的）
- 开关存在之前就已经攒下的

留下的空壳全靠这一下收尾，所以它旁边一直挂着数字：那个数字就是「现在有多少等着被收」。  
（自动清理修好之后，本插件删出来的空目录在删的那一刻就没了，这个数字一般只剩前两种来源。）

这个计数**只在打开配置时读一次**，所以列表页不会为了一个看不见的数字多跑一趟 host。

#### 回收站（第二个标签）

点标签条上的**回收站**，就地切到本插件删过、且仍可还原的会话列表，每条一个  
「还原」按钮。不用离开这一页，也没有第二个导航项要记。  
还原结果以**顶部横幅**提示（不打断操作，几秒后淡出）。  
勾选多条可以**批量还原**或**彻底删除**。  
回收站和会话列表共用**同一套工具栏和分页器**：筛选框独占一行、全选框在下一行最左、  
同样每页 20 / 50 / 100 / 200 —— 两个标签页读起来是一套东西，而不是两个插件。  
回收站也**按分组分块**，小标题同样写分组名（删掉的会话记得自己属于哪个组，  
分组没了就退回删除时记下的那个名字）。  
所以清一批旧记录时不会变成一场长跑。

每一行都会显示**这是什么**，而不是一串 uuid：

```
修复登录 bug                      [还原]
my-project/src · 2026/01/15 09:41:22
wb-xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

- 标题取自删除前的会话名；没有名字的会话回退显示**项目文件夹名**
- 会话 id 仍然保留（等宽小字），用于精确对应
- **旧条目也能显示** —— 之前记录里没存标题的，会从回收站里的会话文件头  
  解出 `cwd` 反推项目名，不需要重新删一遍

还原后会**立刻**出现在左侧列表，并且回到**原来的工作区分组**（删除时会把该会话  
从 `sessionIds` 里摘掉，插件在删除前记下了它属于哪个组，还原时挂回去）。

> 如果那个工作区在这期间被移除了，会话照常还原，只是会落在「未分组」。

### 空工作区怎么处理

删掉某个工作区下的**最后一个**会话时，它就成了一个没有任何会话的空分组。

- **默认什么都不做**：空分组通常代表你还在用的项目目录，删不删由你决定
- 打开「删除后自动清理空分组与空目录」（见上文**配置**）：连分组一起移除，  
  并清掉这次删除在 `sessions/` 下留下的空目录，然后在横幅里报数
- 开关之外攒下来的，用配置里的「清理」一次收尾

移除分组只删分组记录（和它在 `sessions/` 下留下的那个空文件夹）：  
**项目文件夹和会话日志都保留**，和 DSH 官方「删除工作区」的行为一致。  
唯一影响是：如果之后还原一个属于该分组的会话，它会落在「未分组」。

## 删除都做了什么

一次删除会同步清理四处，任何一处漏掉都会产生"幽灵会话"：

| 位置                                  | 不清理的后果          |
| ----------------------------------- | --------------- |
| `$DSH_HOME/sessions/<slug>/<id>/`   | 会话文件还在          |
| `session_projcache` 域               | 侧栏标题缓存还在，列表里仍显示 |
| `workspace` 域的 `sessionIds`         | 掉进「未分组」显示为孤立条目  |
| `workspace` 域的 `archivedSessionIds` | 已归档的会话清理不干净     |

另外会先停止运行中的 agent 并 flush，否则 dispose 时的写入会把刚删的目录重建出来。

## 模型也能用

注册了五个原生工具：

| 工具                 | 用途                                 |
| ------------------ | ---------------------------------- |
| `list_sessions`    | 列出磁盘上所有会话（id + 工作区 slug），按修改时间倒序   |
| `session_delete`   | 删除指定会话；`permanent: true` 时跳过回收站直接删 |
| `list_recycled`    | 列出回收站里仍可还原的会话                      |
| `session_restore`  | 把某个回收站会话还原回原位置                     |
| `workspace_remove` | 移除一个工作区分组（连它留下的空会话目录一起清，保留项目目录和日志） |

所以你可以直接对 AI 说「把 xxx 那个会话删了」。

## 还原

在 **设置 → 会话删除 → 回收站标签** 里点「还原」即可（标签上就有条数，  
不用先猜值不值得点过去），会话**立刻**回到侧边栏，  
并回到它原来的工作区分组。

也可以对 AI 说「把 xxx 还原回来」（`session_restore` 工具）。

数据在哪：删掉的会话被 rename 到 `$DSH_HOME/session-recycle-store/<session-id>/`，  
清单在 `$DSH_HOME/session-recycle-bin.json`。手工把目录挪回去也能恢复，  
但**建议用面板** —— 它会顺带修好分组、清掉回收站条目。

如果清单丢了（误删文件、或写入时崩溃），插件**启动时会自动重建**：  
store 里的每个目录都能从自己的会话头读出 id 和项目路径，所以不会变成孤儿。

> 注意：删除**不会**进操作系统的回收站 / 废纸篓。要恢复请用插件面板。

## 安全设计

- 会话 id 必须匹配 `<prefix>-<uuid>`，路径分隔符与 `..` 一律拒绝
- 每个删除候选都经 `path.resolve` 复核，必须是会话根目录的**直接子目录**，  
  否则直接报错拒绝（`OUT_OF_ROOT`）—— 实测路径穿越、绝对路径全部拦住
- 删除前再校验一次包含关系，不是只在入口校验
- `permanent` 需要显式传 `true`，默认永远是回收站

### 客户端按钮怎么触达 host

浏览器端**没有** `tools` 服务 —— `@deepseek-ai/dsh-tools` 是 host-only 包，  
没有 `./client` 导出，所以 `ctx.get('tools')` 在客户端永远是 `undefined`。  
客户端按钮必须有显式通道才能触达 host。

本插件注册十一条 `exact` 路由（`list` / `delete` / `delete-many` / `settings` /  
`workspaces` / `recycled` / `restore` / `purge` / `remove-workspace` /  
`empty-dirs` / `prune-empty`），  
与社区市场对自己所有写操作的做法一致。因为 `exact` 注册会**优先于** harness  
自带的 `/api` 围栏，这些路由必须自己防守，规则照搬市场已验证的那套：

| 检查                                            | 原因                                                             |
| --------------------------------------------- | -------------------------------------------------------------- |
| `Host` 必须是 loopback（或 `--trusted-host` 声明的授权） | DNS rebinding：攻击页面能让 `Origin === Host` 成立，而 `Host` 是它唯一伪造不了的头部 |
| `sec-fetch-site: cross-site` 直接拒绝             | 浏览器自己声明的跨站                                                     |
| `Origin` **存在**时必须等于 `Host`                   | 跨站页面会被拒                                                        |
| `Origin` **缺失**时放行                            | Desktop 版代理会剥掉它；非浏览器客户端本就能伪造，拒绝没意义                             |
| `Origin: null` 拒绝                             | 沙箱 iframe / `data:` 文档：是"存在但不可解析"，不等于缺失                        |
| body 上限 4 KiB（批量删除 256 KiB），只读已知字段            | 400 而不是解析到 OOM                                                 |

## 与社区同类插件的区别

|         | 本插件                               | 常见的 `dsh-plugin-session-delete`         |
| ------- | --------------------------------- | --------------------------------------- |
| 删除方式    | 移入插件回收站（可还原）                      | `rm -rf` 永久删除                           |
| 触发通道    | 同源守卫的专用路由 + 原生工具                  | 无守卫的 `POST /__chameleon/session/delete` |
| 跨站防护    | 校验 Host / Origin / sec-fetch-site | 无（仅依赖 localhost 绑定）                     |
| 导入会话 id | 原生支持 `wb-` / `codex-` 等前缀         | 正则只认 `session-`，导入的会话删不掉                |

## 兼容性

在 DSH `0.2.0-rc.2`（session format v4）上开发并验证。  
删除逻辑依赖 `sessions` / `agents` / `storageDomain` 服务与


`session_projcache` / `workspace` 两个存储域；这些是当前版本的既有接口。  
`webServer` 是可选依赖：纯终端 profile 没有 web 界面时，插件照常加载，  
只注册工具、不注册路由。
